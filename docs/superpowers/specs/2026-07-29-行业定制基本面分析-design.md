# 行业定制基本面分析设计

> 将现有通用五维度基本面评分升级为 10 集群行业定制版本。每集群专属指标清单、阈值、权重、估值方法，数据获取层带多级 fallback。

---

## 1. 背景与目标

### 1.1 现状

`fundamentals_agent`（`python/valor/agents/fundamentals.py`）硬编码 5 维度（盈利/成长/健康/估值/股东回报）× 3 指标，全局统一阈值（如 ROE>15%、PE<25），不区分行业。问题：银行因"成长性低"被扣分、科技企业因"不分红"被扣分、公用事业因"毛利率低"被扣分——这些扣分发生在该行业非核心竞争力维度，不合理。

### 1.2 目标

按 `docs/strategy/suggestion.md` 建议，采用申万一级行业（31 个）合并为 10 集群，每集群定制：
- 指标清单（增/删/改）
- 阈值（集群专属）
- 权重（如公用事业股东回报 40%、成长 5%）
- 估值方法（银行 PB、周期 PB 分位、科技 PEG、公用事业股息率）

### 1.3 核心原则

行业定制的目标不是让分析变复杂，而是让扣分项更合理——扣分只发生在该行业核心竞争力维度出现恶化时。

---

## 2. 架构总览

### 2.1 方案选型

**方案 A：配置驱动 + 策略模式**（已选）

新建 `python/valor/strategy/industry_clusters.py`，用 Pydantic 模型定义 `IndustryCluster`（含指标清单、阈值、权重、估值方法），10 个集群用 Python 字典常量注册。`fundamentals_agent` 改造为通用执行引擎：查行业 -> 映射集群 -> 按配置执行指标判断 -> 输出动态维度信号。

优点：配置与执行分离，10 集群指标/阈值/权重横向可对比；类型安全；与现有 router/adapter 风格一致。

### 2.2 模块层次

```
python/valor/
├── strategy/                          [新模块]
│   ├── __init__.py
│   ├── industry_clusters.py           # Pydantic 模型 + 10 集群配置常量 + INDUSTRY_TO_CLUSTER 映射
│   ├── cluster_resolver.py            # 行业名 -> 集群 key 的映射函数
│   └── metric_evaluators.py           # 指标判断函数（阈值/趋势/分位）+ evaluate_dimension
├── adapters/data/
│   └── akshare_cache.py               [扩展] 新增 get_stock_industry / get_history_pb / get_bank_special_indicators / get_dividend_history / get_r_and_d_expense
├── tools/
│   └── api.py                         [扩展] get_financial_metrics 按集群追加专属指标 + fallback
├── agents/
│   ├── fundamentals.py                [改造] 配置驱动的执行引擎
│   ├── market_data.py                 [改造] 获取行业+集群，写入 state
│   ├── bull_bear_debate.py            [改造] 读取动态维度
│   ├── risk_manager.py                [改造] 读取动态维度数量
│   └── portfolio_manager.py           [轻改] 透传 industry_profile
```

### 2.3 数据流

```
market_data_agent
  ├─ get_stock_industry(ticker) -> "银行"  [新]
  ├─ cluster_resolver.resolve("银行") -> "financial"
  ├─ get_financial_metrics(ticker, cluster_hint="financial")
  │    -> metrics + bank_special_indicators + pb_percentile_5y(若需)  [扩展]
  └─ state["data"]["industry"] = "银行"
     state["data"]["cluster"] = "financial"

fundamentals_agent
  ├─ cluster = state["data"]["cluster"]
  ├─ config = INDUSTRY_CLUSTERS[cluster]
  ├─ for dimension in config.dimensions:
  │     signals[dim.name] = evaluate_dimension(dim, metrics)
  ├─ overall = weighted_vote(signals, config.weights)
  └─ output: signal + confidence + reasoning + evidence + industry_profile

bull_bear_debate / risk_manager
  └─ 遍历 reasoning.keys() 而非硬编码 5 维度
```

### 2.4 关键原则

- `market_data_agent` 负责采集所有原始数据（含行业标签 + 新增指标 + fallback 预填充），写入 state
- `fundamentals_agent` 纯计算，按集群配置执行，无 IO
- 下游通过 `reasoning` 字段的 keys 动态发现维度，不再硬编码
- 数据获取层每个关键字段带 2-4 级 fallback：主 API -> 备用 API -> 在线搜索 -> LLM 生成 -> None

## 3. 行业分类获取与集群映射

### 3.1 行业获取

新增 `akshare_cache.get_stock_industry(symbol)`，调用 `ak.stock_individual_info_em(symbol)` 取"行业"字段，30 天 TTL 缓存到 `stock_industry` 表。

Fallback 链：
1. AkShare `stock_individual_info_em`
2. LLM 快照（`get_market_snapshot` 模式）
3. None -> 走 conglomerate 集群

### 3.3 东财 vs 申万名称差异

AkShare `stock_individual_info_em` 返回的"行业"字段实际是东财分类，与申万一级名称高度重合但有细微差异。映射表里同时收录已知别名（如"银行" / "银行Ⅱ"）。无法映射的落 `conglomerate` 并打 warning。

### 3.4 全市场行业分布预扫（实施第一步）

抽样验证不足以覆盖所有别名差异。实施第一阶段先跑全市场行业分布统计：

```python
# scripts/scan_industry_distribution.py（一次性脚本）
import akshare as ak
df = ak.stock_zh_a_spot_em()  # 全市场 ~5000 只
# 提取"行业"字段（东财分类），统计去重值 + 每个行业对应股票数量
industry_counts = df["行业"].value_counts().to_dict()
# 输出到 docs/strategy/industry_distribution.json 供映射表校准
```

据统计结果完善 `INDUSTRY_TO_CLUSTER` 映射表：
- 确认 31 个申万一级名在东财分类中的实际名称
- 补充所有别名（如"银行" vs "银行Ⅱ"、"电力设备" vs "电气设备"）
- 统计落入 `conglomerate` 的股票数量，若 >5% 需补充映射
- 将分布统计结果作为测试夹具，验证 `resolve()` 覆盖率

### 3.5 失败回退

行业获取失败 -> `cluster = "conglomerate"` -> 走通用 5 维度框架（等价于现有逻辑）。

## 4. 集群配置模型（Pydantic）

### 4.1 核心模型

定义在 `python/valor/strategy/industry_clusters.py`：

```python
class MetricJudge(str, Enum):
    THRESHOLD_GT = "threshold_gt"      # value > threshold -> bullish
    THRESHOLD_LT = "threshold_lt"      # value < threshold -> bullish
    TREND_UP = "trend_up"              # 同比上升 -> bullish（需两期数据）
    TREND_DOWN = "trend_down"          # 同比下降 -> bullish
    RANGE = "range"                    # low < value < high -> bullish

# 注: 历史 PB 分位数等需历史序列计算的指标, 由数据层算好数值后用 THRESHOLD_LT 判断,
# fundamentals_agent 不感知历史序列, 保持纯计算无 IO。

class FallbackSource(str, Enum):
    NONE = "none"                      # 缺失即跳过，维度按剩余指标评判
    LLM = "llm"                        # 调用 LLM 生成（复用 get_market_snapshot 模式）
    ONLINE_SEARCH = "online_search"    # 调用在线搜索接口补全
    COMPUTED = "computed"              # 用其他已有字段计算替代

class MetricSpec(BaseModel):
    field: str                         # metrics 字段名，如 "net_interest_margin"
    label: str                         # 展示名，如 "净息差"
    judge: MetricJudge
    threshold: float | None = None
    threshold_low: float | None = None
    threshold_high: float | None = None
    fallback: FallbackSource = FallbackSource.NONE
    fallback_hint: str = ""            # LLM/搜索时的提示语
    missing_signal: str = "neutral"    # 缺失且无 fallback 时该指标的默认信号
    period: str = "annual"             # annual / quarterly / ttm，trend 判断时选取对应频率数据
    dynamic_baseline: str | None = None  # 动态基准字段名（如 "industry_avg_nim"），非 None 时 threshold 与该基准比较而非硬编码
    reference_only: bool = False       # True 表示参考项，不计入维度 majority 投票，仅展示
    description: str = ""

class DimensionSpec(BaseModel):
    name: str                          # "profitability" / "growth" / ...
    label: str                         # "盈利能力"
    metrics: list[MetricSpec]
    rule: str = "majority"             # majority(≥半数) / all / any
    weight: float                      # 该维度权重（集群内归一化）

class IndustryCluster(BaseModel):
    key: str                           # "financial"
    label: str                         # "金融"
    dimensions: list[DimensionSpec]
    valuation_method: str              # "pb" / "pe" / "peg" / "pb_percentile" / "dividend_yield"
    notes: str = ""

    @property
    def normalized_weights(self) -> dict[str, float]:
        total = sum(d.weight for d in self.dimensions)
        return {d.name: d.weight / total for d in self.dimensions} if total > 0 else {}
```

### 4.2 Fallback 执行时机

在数据获取层（`tools/api.py` 的 `get_financial_metrics`）完成，而非 fundamentals_agent。每集群配置里标注哪些字段需要 fallback，数据层按标注预填充。fundamentals_agent 只消费已填充的 metrics dict。

### 4.3 指标字段命名约定

- 通用字段（`return_on_equity` 等）沿用现有命名
- 行业专属字段用 snake_case 英文：
  - 金融：`net_interest_margin`、`non_performing_loan_ratio`、`provision_coverage`、`core_tier1_capital_ratio`
  - 地产：`adj_debt_to_asset`、`net_debt_to_equity`、`cash_to_short_debt`、`inventory_turnover`
  - 周期：`pb_percentile_5y`、`capacity_utilization`、`inventory_days_change`
  - 制造：`asset_turnover`、`capex_to_depreciation`、`receivable_to_revenue`
  - 消费：`contract_liability`、`sales_expense_ratio`、`ocf_to_net_profit`
  - 医药/TMT：`r_and_d_to_revenue`、`r_and_d_capitalization_rate`
  - 公用事业：`free_cash_flow`、`dividend_years`、`capex_to_ocf`

## 5. 10 个集群配置内容

每集群只列相对通用框架的差异（增/删/改指标、权重、估值方法）。所有阈值基于 suggestion + A 股经验值校准。

### 5.1 financial（金融）

| 维度 | weight | 指标 | judge | threshold | fallback |
|---|---|---|---|---|---|
| profitability | 0.10 | return_on_equity | threshold_gt | 0.10 | none |
| | | net_interest_margin | threshold_gt | 0.014 | online_search |
| growth | 0.10 | revenue_growth | threshold_gt | 0.05 | none |
| financial_health | 0.35 | non_performing_loan_ratio | threshold_lt | 0.015 | online_search |
| | | provision_coverage | threshold_gt | 2.0 | online_search |
| | | core_tier1_capital_ratio | threshold_gt | 0.085 | llm |
| valuation | 0.25 | price_to_book | threshold_lt | 1.0 | none |
| shareholder_return | 0.20 | dividend_yield | threshold_gt | 0.03 | none |

**估值方法**：pb（<1 看多）
**notes**：银行经营风险而非产品，PE 和成长性意义有限，重点看资产质量。净息差 1.4% 为 2024 年商业银行均值，不同银行类型（国有大行/股份行/城商行）差异较大，与行业均值比较比绝对阈值更准确（支持 dynamic_baseline 字段，实施时若能获取行业均值则动态比较）。

**notes**：类债券属性，现金流稳定增长缓慢，核心看股息稳定性和资本开支效率。growth 维度完全移除--低增长是公用事业常态，不应因此扣分（符合"扣分只发生在核心竞争力维度恶化时"原则）。

### 5.10 conglomerate（综合，兜底）

沿用现有 5 维度框架，阈值与 `fundamentals.py` 现有硬编码值完全一致（ROE>15%、net_margin>20%、operating_margin>15%、revenue_growth>10% 等），各维度等权 0.20，估值方法 pe。确保未识别行业行为与改造前完全一致（回归锚点）。

### 5.11 权重校验

每集群维度权重之和 = 1.0，实施时用 Pydantic validator 校验。

### 5.12 阈值校准依据

### 5.13 动态阈值机制

对于行业均值类指标（净息差、不良率、毛利率等），硬编码阈值会随宏观环境失效（如降息周期净息差下行）。引入 `dynamic_baseline` 字段支持动态基准：

**配置示例**：
```python
MetricSpec(
    field="net_interest_margin",
    label="净息差",
    judge=MetricJudge.THRESHOLD_GT,
    threshold=0.014,                # 硬编码默认值（fallback）
    dynamic_baseline="industry_avg_nim",  # 动态基准字段名
    fallback_hint="商业银行净息差约1.4%",
)
```

**执行逻辑**：`evaluate_metric` 时若 `metrics[dynamic_baseline]` 存在且 > 0，则用动态基准替代硬编码 threshold（如 NIM > industry_avg_nim 看多）；否则回退到硬编码 threshold。

**动态基准获取**：数据层（`get_financial_metrics`）按集群可选获取行业均值：
- 银行：`ak.stock_sector_hist`（东财行业板块历史）或央行金融统计数据
- 消费/周期：东财行业板块平均毛利率
- 若行业均值获取失败，回退到硬编码 threshold（不阻断流程）

**时效性标注**：每个硬编码阈值在配置 `description` 中标注数据来源与截至时间，便于后续定期校准。动态基准为首选，硬编码为 fallback。

### 5.14 维度移除原则

对"完全不相关"的维度（权重 ≤5% 且与核心竞争力无关），完全移除而非降权，符合"扣分只发生在核心竞争力维度恶化时"原则：
- utility_transport：移除 growth（低增长是常态）
- tmt：移除 shareholder_return（成长型科技不分红是常态）
- 其他集群保留全部 5 维度但调整权重

```python
@agent_endpoint("fundamentals", "基本面分析师，按行业集群定制评分")
def fundamentals_agent(state: AgentState):
    data = state["data"]
    metrics = data["financial_metrics"][0]
    cluster_key = data.get("cluster", "conglomerate")

    elif overall < -0.2:

    else:

        "reasoning": reasoning,
        "risk_flags": [],

            "cluster": config.key,
            "cluster_label": config.label,
            "industry": data.get("industry", ""),
            "valuation_method": config.valuation_method,
            "notes": config.notes,
        },
    }
    # HumanMessage 构造 + state 返回（与现有模式一致）
```

### 6.2 evaluate_dimension 逻辑

`strategy/metric_evaluators.py`：

```python
def evaluate_dimension(dim, metrics) -> tuple[str, str, list[dict]]:
    results = []
    for spec in dim.metrics:
        value = metrics.get(spec.field)
        if value is None or value == 0:
            results.append({"label": spec.label, "value": None,
                            "passed": False, "skipped": True,
                            "reference_only": spec.reference_only})
            continue
        passed = evaluate_metric(spec, value, metrics)
        results.append({"label": spec.label, "value": value, "passed": passed,
                        "reference_only": spec.reference_only})

    # 仅用非 reference_only 的指标投票
    voting = [r for r in results if not r.get("reference_only")]
    if not voting:
        # 全部为参考项或全部缺失，维度信号 neutral
        return "neutral", _build_details(results), results
    passed_count = sum(1 for r in voting if r.get("passed"))
    total = len(voting)
    if dim.rule == "majority":
        signal = "bullish" if passed_count >= total / 2 else (
            "bearish" if passed_count == 0 else "neutral")
    elif dim.rule == "all":
        signal = "bullish" if passed_count == total else "neutral"
    elif dim.rule == "any":
        signal = "bullish" if passed_count > 0 else "bearish"
    return signal, _build_details(results), results
```

### 6.3 evaluate_metric 按 judge 分发

- `threshold_gt` / `threshold_lt`：直接比较。若 `spec.dynamic_baseline` 存在且 `metrics[dynamic_baseline]` 有效，用动态基准替代 `threshold`
- `range`：threshold_low < value < threshold_high
- `trend_up` / `trend_down`：按 `spec.period` 选取对应频率的两期数据对比
  - `annual`：`financial_metrics[0]` vs `[1]`（年报同比）
  - `quarterly`：`financial_metrics[0]` vs `[1]`（最新季报 vs 去年同期，需数据层按报告日对齐）
  - `ttm`：TTM 口径同比（数据层预算）
  - 数据层 `get_financial_metrics` 返回的 list 按报告日降序，`[0]` 最新 `[1]` 上期，period 仅影响 trend 类判断的语义解释
- `reference_only=True` 的指标：执行判断并展示结果，但**不计入维度 majority 投票**，仅作为 LLM 上下文参考

注：历史分位数类指标（如 `pb_percentile_5y`）由数据层算好数值放入 metrics，此处用 `threshold_lt` 判断即可。

### 6.4 输出结构变化

1. `reasoning` 的 key 从固定 5 个变为动态（视集群而定）
2. 新增 `industry_profile` 字段，供下游 LLM agent 引用集群上下文
3. `evidence` 字段扩展：除通用字段外，包含集群专属指标数值

### 6.5 confidence 计算

原逻辑 `max(bullish, bearish) / total`，新逻辑 `|weighted_score|`（0~1）。加权后更反映权重影响，如公用事业股东回报维度权重 0.40，其信号方向主导 confidence。

### 6.6 向后兼容

conglomerate 集群配置等价于现有 5 维度逻辑，保证未识别行业的输出与改造前一致。

### 7.4 Fallback 实现模式

```python
def _fetch_bank_metrics_with_fallback(symbol: str) -> dict:
    result = {}
    # Level 1: AkShare 银行专项
    try:
        bank_data = get_bank_special_indicators(symbol)
        if bank_data:
            result.update(bank_data)
    except Exception as e:
        logger.warning("Bank special indicators fetch failed: {e}", e=e)

    # Level 2: ONLINE_SEARCH 补全缺失字段
    missing = [f for f in ["net_interest_margin", "non_performing_loan_ratio",
                           "provision_coverage", "core_tier1_capital_ratio"]
               if f not in result or result.get(f) is None]
    if missing:
        try:
            searched = _online_search_metrics(symbol, missing)
            result.update(searched)
        except Exception:
            pass

    # Level 3: LLM 生成剩余缺失
    still_missing = [f for f in missing if f not in result or result.get(f) is None]
    if still_missing:
        try:
            llm_generated = _llm_estimate_metrics(symbol, still_missing)
            result.update(llm_generated)
        except Exception:
            pass

    # Level 4: 全失败则字段保持 None，fundamentals_agent 跳过
    return result
```

### 8.1 `bull_bear_debate.py` 改造

```python
def _build_dimension_block(fundamentals_msg: dict) -> str:
    reasoning = fundamentals_msg.get("reasoning", {})
    profile = fundamentals_msg.get("industry_profile", {})
    lines = [f"行业集群: {profile.get('cluster_label', '通用')} "
             f"(估值方法: {profile.get('valuation_method', 'pe')})"]
    for dim_name, dim_data in reasoning.items():
        lines.append(
            f"  - {dim_name}: {dim_data['signal']} "
            f"(权重 {dim_data.get('weight', 0):.0%}) - {dim_data['details']}"
        )
```

### 8.2 `risk_manager.py` 改造

**现状**：`risk_manager.py:144-175` 当辩论置信度为 0 时，回退到"5 个维度 Agent 的信号投票"。硬编码读取 5 个维度。

**改造**：回退投票逻辑改为读取 `fundamental_analysis.reasoning` 的实际维度数。

```python
def _fallback_signal_vote(fundamentals_msg: dict) -> tuple[str, float]:
    reasoning = fundamentals_msg.get("reasoning", {})
    signals = [d["signal"] for d in reasoning.values()]
    weights = [d.get("weight", 1.0 / len(signals)) for d in reasoning.values()]
    score = sum(w * {"bullish": 1, "bearish": -1, "neutral": 0}[s]
                for w, s in zip(weights, signals))
    if score > 0.2:
        return "bullish", min(abs(score), 1.0)
    elif score < -0.2:
        return "bearish", min(abs(score), 1.0)
    return "neutral", abs(score)
```

### 8.3 `portfolio_manager.py` 改造

**现状**：`portfolio_manager.py:91-117` 收集各 Agent 消息喂给 LLM。基本面权重 30%、估值权重 35%（`portfolio_manager.py:303-312`）。

## 10. 实施风险与缓解

### 10.1 AkShare 接口可用性

部分新增接口（`stock_a_lg_indicator`、银行专项）需实施时验证。若不可用，走 fallback 链（ONLINE_SEARCH / LLM）。

**缓解**：实施第一阶段先跑通 `get_stock_industry` + `get_history_pb` + `get_bank_special_indicators` 的接口可用性验证，确认后再铺开。

### 10.2 东财行业名与申万一级差异

AkShare 返回的"行业"字段是东财分类，与申万一级名称可能有细微差异（如"银行" vs "银行Ⅱ"）。

**缓解**：实施第一步跑全市场行业分布预扫（见 3.4），统计所有去重行业名 + 股票数量，据此完善 `INDUSTRY_TO_CLUSTER` 映射表。统计落入 conglomerate 的股票比例，若 >5% 需补充映射。

### 10.3 下游硬编码访问

`reasoning["profitability_signal"]` 等硬编码访问会 KeyError。

**缓解**：实施时全局 grep `profitability_signal\|growth_signal\|financial_health_signal\|price_ratios_signal\|shareholder_return_signal`，确认所有访问点改为动态遍历。

### 10.4 prompt 模板硬编码五维度

`prompts/bull_bear_debate/system.md` 可能硬编码"请从以下五个维度分析：盈利能力、成长性…"，导致维度数量变化后 LLM 输出结构偏离。

**缓解**：实施前 `grep -n "盈利能力\|成长性\|财务健康\|估值比率\|股东回报" prompts/bull_bear_debate/*.md` 确认硬编码程度，改为动态占位符 `{dimensions_list}`。

### 10.5 历史 PB 序列获取

`stock_a_lg_indicator` 可能只覆盖部分股票。

**缓解**：fallback 到 ONLINE_SEARCH，再 fallback 到当前 PB 单点（无法算分位则该指标跳过，cyclical_resource 的 valuation 维度按剩余投票指标判断；若全部缺失则维度 neutral）。

### 10.6 银行专项指标解析

银行三表字段与普通企业不同（如无"存货"、有"贷款及垫款"），解析逻辑需特殊处理。

**缓解**：`get_bank_special_indicators` 独立实现，不与通用三表解析耦合；失败走 LLM 生成。

### 10.7 动态阈值基准获取

`dynamic_baseline` 依赖行业均值数据（如 `industry_avg_nim`），`ak.stock_sector_hist` 可能不提供细分行业的净息差/不良率均值。

**缓解**：动态基准为可选增强，获取失败时回退到硬编码 threshold（不阻断流程）。首批实施只对银行 NIM/不良率启用动态基准，其他指标保持硬编码。

### 10.8 阈值时效性

硬编码阈值随宏观环境失效（如降息周期净息差下行、行业平均毛利率变化）。

**缓解**：每个阈值在 `description` 标注数据来源与截至时间（见 5.12 表格）。建议每季度 review 一次关键阈值，动态基准机制（5.13）逐步替代硬编码。
